# سند جامع معماری سامانه املاک سقف (Saghf System Architecture)

این مستند تشریح‌کننده استانداردها، اصول طراحی و ساختار معماری پلتفرم سقف است. تمامی توسعه‌دهندگان و دستیاران هوش مصنوعی ملزم به رعایت کامل اصول مندرج در این سند هستند.

---

## ۱. اصل بنیادین تقارن سه‌گانه پلتفرم‌ها (Tri-Platform Feature Parity)

در پلتفرم سقف، هیچ پلتفرمی نسبت به پلتفرم دیگر برتری یا اولویت توسعه ندارد. هر قابلیت جدید یا تغییری که در سامانه اعمال می‌شود، باید به صورت متقارن و هم‌زمان در هر سه درگاه اصلی پیاده‌سازی و تست گردد:

```
                          ┌───────────────────────────┐
                          │   موتور مرکزی سقف (Core)   │
                          │  Database + Dual CRM Store │
                          └─────────────┬─────────────┘
                                        │
           ┌────────────────────────────┼────────────────────────────┐
           │                            │                            │
           ▼                            ▼                            ▼
┌─────────────────────┐      ┌─────────────────────┐      ┌─────────────────────┐
│    وب‌اپلیکیشن       │      │     ربات تلگرام     │      │      ربات بله       │
│      (Web App)      │      │    (Telegram Bot)   │      │      (Bale Bot)     │
│  http://127.0.0.1   │      │     @saghf_bot      │      │     @saghf_bot      │
└─────────────────────┘      └─────────────────────┘      └─────────────────────┘
```

## ۲. معماری اتوماسیون دو هسته‌ای و رفع وابستگی (Dual-Engine Architecture / Zero Lock-in)

### حل دائمی دغدغه محدودیت ۱۴ روزه رایگان n8n Cloud:
سامانه سقف به نحوی معماری شده است که اتوماسیون فرآیندها هرگز وابسته به یک سرویس ابری خاص نباشد:

1. **هسته اول — اتوماسیون تصویری n8n (Visual Automation Layer):**
   - از n8n به عنوان بستر تست، نمونه‌سازی سریع و نظارت بصری بر جریان داده‌ها استفاده می‌شود.
   - کلیه پلتفرم‌ها (Web, Telegram, Bale) از طریق وب‌هوک به n8n متصل هستند.
   - **الزام پشتیبان‌گیری:** تمامی ورک‌فلوها در قالب فایل‌های JSON استاندارد در پوشه `n8n_workflows/` سورس‌پروژه ذخیره و نگهداری می‌شوند تا در هر زمان بتوان آن‌ها را در هر سرور محلی (Docker / Self-Hosted n8n) بالا آورد.

2. **هسته دوم — موتور بومی پایتون (Native Embedded Engine):**
   - پکیج `services/omnichannel_engine.py`، `services/crm_dual_store.py` و `services/nurturing_engine.py` به‌صورت کاملاً مستقل و موازی در بک‌اند سقف فعال هستند.
   - با انقضای مهلت ۱۴ روزه آزمایشی n8n Cloud، سیستم به‌صورت ۱۰۰٪ بدون هزینه و بدون نیاز به هیچ مداخله‌ای، از طریق موتور داخلی به پردازش، تفکیک معنایی، ثبت در CRM و ارسال آلارم‌ها ادامه می‌دهد.

## ۴. استانداردهای کدنویسی و خط قرمزها
1. **قانون ۱:** ممنوعیت قطعی هرگونه `git commit` یا `git push` بدون دستور صریح کاربر.
2. **قانون ۲:** داده‌ها باید واقعی باشند و تمامی آگهی‌ها حاوی لینک معتبر همراه با تگ صریح `<a href="...">لینک آگهی</a>` باشند.
3. **قانون ۳:** رعایت اصل برابری سه‌پلتفرمی در تمام کامپوننت‌ها و ویژگی‌های جدید.
4. **قانون ۴:** ذخیره‌سازی دائمی ورک‌فلوهای n8n در `n8n_workflows/` و همگامی موتور بومی پایتون.
