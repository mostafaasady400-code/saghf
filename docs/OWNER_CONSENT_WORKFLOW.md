# صف پشتیبانی و مدیریت سقف

اجرا از ریشه پروژه: `python -m crawler.guarded_web --port 5001`

صف: `/owner-consent/` (صفحه‌بندی ۲۵ رکوردی). فرم یک آگهی: `/owner-consent/<archive_id>`.
برای رکورد واقعی قبلی مسیر `/owner-consent/47` است؛ هیچ رضایت واقعی برای آن توسط ایجنت ثبت نشده.

- حساب فعال نقش agent برای پشتیبانی، admin/super_admin برای مدیریت؛ مجوز از دیتابیس خوانده می‌شود.
- پشتیبانی رضایت واقعی را دریافت می‌کند، روش و کد مرجع داخلی را ثبت می‌کند. فقط هش مرجع ذخیره می‌شود.
- مدیری غیر از ثبت‌کننده، مستند را بازبینی می‌کند؛ بررسی معتبر مالکیت تیم نیز لازم است.
- رضایت مربوط به پیگیری همین آگهی و نمایش اطلاعات به کارکنان مجاز سقف، نه انتشار عمومی است.
- تصمیم‌های دومرحله‌ای در `instance/owner-consent.sqlite3` مستقل از اسکیماهای آنتی‌گراویتی و خارج از Git ذخیره می‌شوند.
- وضعیت‌های لغو/رد بلافاصله معتبر هستند؛ انقضا، تغییر متن/مشخصات/قیمت یا رد مالکیت، تأیید مشترک را غیرفعال می‌کند.
- CSRF، سابقه افزایشی، تطابق snapshot و تعارض فرم قدیمی محافظت می‌شوند؛ خطای SQLite نتیجه تأییدشده نمی‌سازد.
- این نسخه شماره جمع‌آوری یا نمایش نمی‌دهد و به OTP یا کرولر شماره متصل نیست. ثبت رضایت و تصمیم انسانی به معنی اثبات مستقل مالکیت یا کنترل شماره نیست.
- اجرای مستقیم `app.py` این ماژول مستقل را فعال نمی‌کند؛ از فرمان guarded_web بالا استفاده کنید.

تست: `python -m pytest -q tests/test_owner_consent_registry.py tests/test_team_ownership_review.py tests/test_listing_verification.py tests/test_strict_owner_guard.py`

تست‌ها از حساب‌ها و دیتابیس‌های ایزوله استفاده می‌کنند؛ موفقیت تست، دریافت رضایت واقعی مالک نیست.
